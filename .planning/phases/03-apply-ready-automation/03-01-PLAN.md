<objective>
Build the autonomous triage and queue-building layer for Phase 3 by reusing the existing batch worker pipeline instead of inventing a new execution engine. The new orchestration should read discovered roles from `data/pipeline.md`, skip duplicates or already-handled jobs, run the existing evaluation worker flow, and persist only queue-worthy roles into a dedicated apply queue artifact using the locked gate: score `>= 4.0`, ATS `>= 70`, legitimacy not suspicious.

Purpose: This plan establishes the apply-ready queue as a first-class user artifact and creates the unattended preparation path that keeps the queue filled without the user pasting one job URL at a time.

Output: `prep-apply-queue.mjs`, updated `batch/batch-runner.sh`, updated config/docs for apply-queue automation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `data/pipeline.md` → `batch/batch-input.tsv` | Unreviewed discovered roles are converted into worker input; duplicate and stale entries must be filtered before expensive prep begins |
| Batch worker JSON output → `data/apply-queue.md` | Queue state is derived from machine-readable worker output; malformed parsing could admit bad jobs or reject good ones |
| User config in `config/profile.yml` → unattended prep behavior | Threshold and cap values directly influence autonomous queue growth and must stay user-owned |

## Threats / Failure Modes

| ID | Type | Risk | Mitigation |
|----|------|------|------------|
| T-03-01 | Integrity | Duplicate jobs repeatedly re-enter the queue from `data/pipeline.md` | Filter against both `data/applications.md` and `data/apply-queue.md` before worker launch |
| T-03-02 | Resource exhaustion | Autonomous prep generates too many queued jobs or artifacts | Enforce config-driven `batch_cap` and gate before queue insertion |
| T-03-03 | Logic error | Suspicious or low-fit jobs enter the queue because score/ATS/legitimacy parsing is inconsistent | Consume structured JSON fields from batch worker output and centralize gating in `prep-apply-queue.mjs` |
| T-03-04 | Safety drift | Queue automation evolves into application submission | Keep queue statuses and docs explicitly scoped to review/prep only; no browser submit step in this plan |
</threat_model>
