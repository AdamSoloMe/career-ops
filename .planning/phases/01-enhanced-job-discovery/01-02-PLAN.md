```yaml
name: Daily Job Discovery

on:
  schedule:
    - cron: '0 7 * * *'   # 7 AM UTC daily
  workflow_dispatch:       # Manual trigger; also prevents GitHub 60-day inactivity disable

permissions:
  contents: write          # Required for git-auto-commit-action to push back to main

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          persist-credentials: true   # Required: without this, the push-back fails on protected repos

      - uses: actions/setup-node@v6
        with:
          node-version: '20'

      - run: npm install

      - name: Run scanner
        env:
          ADZUNA_APP_ID: ${{ secrets.ADZUNA_APP_ID }}
          ADZUNA_APP_KEY: ${{ secrets.ADZUNA_APP_KEY }}
          SERPAPI_KEY: ${{ secrets.SERPAPI_KEY }}
        run: node scan.mjs

      - uses: stefanzweifel/git-auto-commit-action@v7
        with:
          commit_message: 'chore(scan): daily discovery run'
          file_pattern: 'data/pipeline.md data/scan-history.tsv'
          # Scoped file_pattern is critical — do NOT use '.' (would commit any stray file changes)
```

Notes on each decision:
- `cron: '0 7 * * *'` = 7 AM UTC daily. User can change this to any cron expression.
- `workflow_dispatch:` is mandatory — without it, GitHub auto-disables the cron after 60 days of repo inactivity.
- `permissions: contents: write` — minimum required for git-auto-commit-action. Do NOT add `pull-requests: write` (not needed).
- `persist-credentials: true` on checkout — without this the push step fails silently on repos with branch protection.
- Secrets are referenced as `${{ secrets.ADZUNA_APP_ID }}` — GitHub masks these in logs automatically.
- `file_pattern` is scoped to exactly `data/pipeline.md data/scan-history.tsv` — not `.` or `data/`.
- If neither pipeline.md nor scan-history.tsv changed, git-auto-commit-action creates no commit (no-op).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub repo secrets → Actions runner env | API keys stored as encrypted secrets, injected into runner environment |
| Actions runner → git push to main | Workflow has write access to repo contents via GITHUB_TOKEN |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | API keys in workflow logs | mitigate | Secrets referenced as `${{ secrets.X }}` — GitHub automatically masks these values in all log output; never echo secrets directly |
| T-02-02 | Tampering | git-auto-commit-action file_pattern | mitigate | `file_pattern` scoped to `data/pipeline.md data/scan-history.tsv` only — prevents any other modified file from being committed by the automation |
| T-02-03 | Elevation of Privilege | workflow permissions | mitigate | `permissions: contents: write` only — minimum required; no `id-token: write`, no `packages: write`; no admin access |
| T-02-04 | Denial of Service | GitHub Actions 60-day inactivity disable | mitigate | `workflow_dispatch:` trigger present — user can manually trigger to keep workflow active; documented in workflow comment |
| T-02-05 | Spoofing | Commit identity (who authored the scan commit) | accept | git-auto-commit-action commits as the Actions bot (`github-actions[bot]`); this is standard, expected, and auditable in commit history |
</threat_model>
