# Plan 01-03: Zero-Key Aggregator Scrapers

## Objective

Extend `scan.mjs` with additional zero-API-key job sources so the pipeline discovers jobs
from companies NOT in `tracked_companies` — making the manually-curated company list
optional rather than the primary discovery mechanism.

## Context

The user requested that career-ops find companies automatically without requiring manual
portals.yml maintenance. Phase 1 already has Adzuna + SerpAPI (keyed) and direct ATS
APIs (from tracked_companies). This plan adds zero-key aggregators that broaden coverage
automatically on every daily scan.

## Architecture Pattern

Each aggregator follows the same interface:
```js
async function fetchSourceName(config, titleFilter, seenUrls, seenCompanyRoles)
  → { results: [{title, company, url, location, source}], errors: [{company, error}] }
```

Config block in `portals.yml` controls enabled/disabled per source.
Results merge into `newOffers` in main(). Per-source count printed in summary.

## Completed in This Session

### ✅ RemoteOK (`remoteok.enabled` in portals.yml)
- **API:** `https://remoteok.com/api` — public JSON, no key, ~500KB payload
- **Fields used:** `position` (title), `company`, `slug` → URL, `location`
- **Filter:** client-side `titleFilter()` on `position`
- **Result:** ~10 new remote jobs per scan (after dedup against tracked_companies)
- **Code:** `fetchRemoteOK()` in scan.mjs ~L120

### ✅ newgrad-jobs.com (`newgrad_jobs.categories` in portals.yml)
- **Source:** Static HTML listing page at `/list-software-engineer-jobs`
- **Parsing:** Regex on href slugs (`title_at_company_id`) → title + company via `toTitleCase()`
- **Result:** ~50 new entry-level jobs per scan
- **Code:** `fetchNewGradJobs()` in scan.mjs

### 2. Add Hacker News "Who's Hiring" scraper (monthly source)
HN posts a "Who's Hiring?" thread the first weekday of each month. Jobs are comments
with company + role + location + apply link. This reaches companies that don't post
on Greenhouse/Lever/Ashby.

**Approach:**
- Fetch latest HN Who's Hiring thread ID from: `https://hacker-news.firebaseio.com/v0/user/whoishiring/submitted.json`
- Get top-level comments: `https://hacker-news.firebaseio.com/v0/item/{id}.json`
- For each comment, fetch: `https://hacker-news.firebaseio.com/v0/item/{commentId}.json`
- Parse `text` field (HTML) for: title, company, URL (apply link), location
- Skip if `dead: true` or no URL found
- Rate limit: fetch max 200 comments, 50ms delay between requests

**Config block to add to portals.yml:**
```yaml
hn_hiring:
  enabled: true
  max_comments: 200
```

**Function signature:**
```js
async function fetchHNHiring(config, titleFilter, seenUrls, seenCompanyRoles)
  → { results, errors }
```

**URL extraction regex:** Find first `href="(https?://[^"]+)"` in comment HTML that isn't
HN itself (`news.ycombinator.com`).

**Title extraction:** First line of comment text before `|` or newline is usually
`Company | Role | Location | Remote/Onsite`.
